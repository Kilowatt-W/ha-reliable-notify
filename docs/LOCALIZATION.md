# German and English / Deutsch und Englisch

All new user-facing interface text must ship in German and English. Keep setup/options, service metadata, select option labels (`selector` section, referenced via `translation_key`) and entity translations in `strings.json` (English source), `translations/en.json` and `translations/de.json` in sync. The admin panel and card share the `RN_TRANSLATIONS` catalog in `reliable-notify-card.js`; use `rnTranslate` / `this.t()` at UI boundaries and `rnValueLabel` for technical values such as priority, strategy, status or log level (the stored value stays unchanged). Backend errors are shown through their error code (`errorText`). Language comes from the HA profile, with English as the fallback. Texts the backend sends to people (action buttons, Telegram callback answers) live in `i18n.py` and follow the HA system language; real test notifications follow the admin's profile language. Add a UI test for new controls in both languages. Never translate stored aliases, entity IDs, service names, message bodies, secrets or YAML/API keys. Provider errors and raw diagnostics may retain their original text.

Neue Oberflächentexte müssen immer auf Deutsch und Englisch vorliegen. Einrichtung, Optionen, Aktionsbeschreibungen, Auswahlwerte (`selector`-Abschnitt, über `translation_key` verknüpft) und Entitätsübersetzungen in `strings.json` (englische Quelle), `translations/en.json` und `translations/de.json` synchron halten. Panel und Karte verwenden gemeinsam `RN_TRANSLATIONS` in `reliable-notify-card.js`; UI-Texte über `rnTranslate` / `this.t()` ausgeben, technische Werte wie Priorität, Strategie, Status oder Loglevel über `rnValueLabel` (der gespeicherte Wert bleibt unverändert). Backend-Fehler werden über ihren Fehlercode übersetzt (`errorText`). Texte, die das Backend an Personen sendet (Aktionsknöpfe, Telegram-Rückmeldungen), stehen in `i18n.py` und folgen der HA-Systemsprache; echte Testnachrichten folgen der Profilsprache des Administrators. Die HA-Profilsprache bestimmt die Sprache, Englisch dient als Rückfall. Neue Bedienelemente in beiden Sprachen testen. Gespeicherte Zielnamen, Entitäts-IDs, Aktionsnamen, Nachrichtentexte, Zugangsdaten und YAML-/API-Schlüssel niemals übersetzen. Fehler externer Dienste und technische Diagnosedaten können im Originaltext bleiben.
